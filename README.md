# SRS-map2map
A trained super-resolution model for N-body cosmological simulation

The original model super-resolves the output of N-body cosmological simulation. It generates 8^3 times more tracer particles and produces their full phase-space (displacement+velocity) distribution. This is the CPU version of the model with the option to run on GPU and the experiments on the model with 2^3 super-resolution factor.

Here is an illustration of the SR field generated by our model, for more detailed description, check the work [Paper-II](https://doi.org/10.1093/mnras/stab2113).

## Model

`SRmodel/G_z0.pt` and `SRmodel/G_z2.pt` are the trained SR models to super-resolve the N-body cosmological simulation at z=2 and z=0 separately. They are the models used in [Paper-II](https://doi.org/10.1093/mnras/stab2113)

For details of the model architecture and training, check repository [map2map](https://github.com/eelregit/map2map), also [Paper-I](https://www.pnas.org/content/118/19/e2022038118) and [Paper-II](https://doi.org/10.1093/mnras/stab2113).

## Usage

We use [MP-Gadget](https://github.com/MP-Gadget/MP-Gadget) to run cosmological simulation for the LR input. The input and output snapshots are stored in [bigfile](https://github.com/rainwoodman/bigfile) format.

### Basic Pipeline

**Step 1** : Run a low-resolution N-body simulation. Our model is trained on LR sets with {Ng_lr=64, Boxsize=100 Mpc/h}. 

**Step 2** : `preproc.py` converts the snapshot to a 3D image. For usage, check `scripts/preproc.slurm`.
- Now supports random sampling with `--sample-size` option
- Can output sampled particles in BigFile format with `--sampled-output`

**Step 3** : `lr2sr.py` uses the trained SR model to super-resolve the LR input.

### Data Processing Tools

**Preprocessing Tools**:
- `preproc.py`: Convert simulation data to field format
  ```bash
  # Basic usage
  python preproc.py --inpath input.bigfile --outpath field.npy
  
  # With random sampling
  python preproc.py --inpath input.bigfile --outpath field.npy --sample-size 32768 --sampled-output sampled_particles
  ```

**Downsampling Tools**:
- `down_sample.py`: Downsample field data
  ```bash
  python down_sample.py --input input_field.npy --output output_field.npy --downsample-factor 32
  ```

### Visualization Tools

**Command Line Tools**:
- `visualize_lr.py`: For LR simulations
- `visualize_hr.py`: For original HR simulations
- `visualize_sr.py`: For SR outputs

**Interactive Notebook**:
- `vis_notebook.ipynb`: Jupyter notebook for interactive visualization
  - Supports all simulation types (LR/HR/SR)
  - Adjustable visualization parameters
  - Interactive 3D plots
  - Built-in documentation

## Notes

- All visualization tools support downsampling for better performance
- Positions are automatically converted from kpc/h to Mpc/h for visualization
- LaTeX rendering is supported if installed
- Random sampling preserves particle relationships (ID/Position/Velocity)

- `lr2sr.py` assumes you use a GPU node. If you use a CPU node instead (which would be much slower), you might need to change `lr2sr.py#30` to `device = torch.device('cpu')`.

- Because of GPU memory limitations, we chunk the LR input to pieces of `nsplit^3` for SR operation. You can set the `nsplit` argument larger if out of GPU memory, but make sure that `nsplit` divides Ng_lr.

- The models are trained on WMAP9 cosmology (see `scripts/LR-sim/paramfile.genic`). It might extrapolate to other cosmologies, but this is not well calibrated yet.

- Visualization tools support LaTeX rendering for high-quality plots if LaTeX is installed on your system.

- The downsampling tools preserve the structure of the data while reducing the number of points, useful for visualization and analysis of large datasets.

## Network Architectures

### Original Network (8× Upsampling)
The original model (`G_z0.pt`, `G_z2.pt`) performs 8× upsampling in each dimension:
- Input: 64³ particles
- Output: 512³ particles
- Trained on WMAP9 cosmology

### Modified Networks (2×, 4×, or 8× Upsampling)
Modified versions using a subset of blocks from the original network:
- **2× Network**: Uses first block only
  - Input: 32³ → Output: 64³
- **4× Network**: Uses first two blocks
  - Input: 32³ → Output: 128³
- **8× Network**: Uses first three blocks
  - Input: 32³ → Output: 256³

To create a modified model:
```bash
python generator.py --num-blocks 2  # For 4× upsampling
# Creates SRmodel/G_z0_modified_4x.pt
```

### Workflow Examples

Starting point: Simulation in BigFile format (ready for visualization)

#### Using Original 8× Network
```bash
# Step 1: Convert simulation to field data
python preproc.py --inpath path/to/original/sim --outpath path/to/field_processed.npy

# Step 2: Apply super-resolution
python lr2sr.py --input path/to/field_processed.npy --output path/to/sr_8x
# Output is in BigFile format, ready for visualization
```

#### Using 2× Network
```bash
# Step 1: Downsample to field data
python down_sample.py --input path/to/original/sim --output path/to/field --downsample-factor 32

# Step 2.1: Convert to BigFile for visualization and preprocessing
python field2bigfile.py --input path/to/field.npy --output path/to/bigfile


# Step 2.2: Process field data
python preproc.py --inpath path/to/bigfile --outpath path/to/field_processed.npy

# Step 3: Apply super-resolution with 2× network
python lr2srx2.py --input path/to/field_processed.npy --output path/to/sr_2x
# Output is in BigFile format, ready for visualization
```

For visualization at any stage:
```bash
# Original simulation
python visualize_hr.py --input path/to/original/sim

# Downsampled data (if converted to BigFile)
python visualize_lr.py --input path/to/bigfile

# Super-resolved results
python visualize_sr.py --input path/to/sr_2x  # For 2× network

```
