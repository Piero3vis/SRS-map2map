# SRS-map2map
A trained super-resolution model for N-body cosmological simulation

The model super-resolves the output of N-body cosmological simulation. It generates 512 times more tracer particles and produces their full phase-space (displacement+velocity) distribution.

Here is an illustration of the SR field generated by our model, for more detailed description, check the work [Paper-II](https://doi.org/10.1093/mnras/stab2113).

![SR-image](https://github.com/yueyingn/SRS-map2map/blob/main/SR-img.png)

## Model

`SRmodel/G_z0.pt` and `SRmodel/G_z2.pt` are the trained SR models to super-resolve the N-body cosmological simulation at z=2 and z=0 separately. They are the models used in [Paper-II](https://doi.org/10.1093/mnras/stab2113)

For details of the model architecture and training, check repository [map2map](https://github.com/eelregit/map2map), also [Paper-I](https://www.pnas.org/content/118/19/e2022038118) and [Paper-II](https://doi.org/10.1093/mnras/stab2113).

## Usage

We use [MP-Gadget](https://github.com/MP-Gadget/MP-Gadget) to run cosmological simulation for the LR input. The input and output snapshots are stored in [bigfile](https://github.com/rainwoodman/bigfile) format.

### Basic Pipeline

**Step 1** : Run a low-resolution N-body simulation. Our model is trained on LR sets with {Ng_lr=64, Boxsize=100 Mpc/h}. The test LR simulation should be in the same resolution (e.g., {Ng_lr=128, Boxsize=200 Mpc/h}). In `scripts/LR-sim`, we provide the parameter files used to run LR simulation with [MP-Gadget](https://github.com/MP-Gadget/MP-Gadget).

**Step 2** : `preproc.py` converts the snapshot of N-body simulation to a 3D image with 6 channels, in shape of `(Nc,Ng,Ng,Ng)`. Here `Nc=6` are the normalized displacement + velocity field of tracer particles arranged by their original grid. For usage, check `scripts/preproc.slurm` as an example job script.

**Step 3** : `lr2sr.py` uses the trained SR model to super-resolve the LR input and output the `Position` and `Velocity` column of 512 more tracer particles as the SR output. For usage, check `scripts/lr2sr.slurm` as an example job script.

### Additional Utilities

**Visualization Tools**:
- `visualize_lr.py`: Visualize LR simulation data
  ```bash
  python visualize_lr.py --input path/to/data --downsample-factor 64
  ```
- `visualize_sr.py`: Visualize SR simulation data
  ```bash
  python visualize_sr.py --inpath path/to/data --downsample-factor 64
  ```

**Data Processing Tools**:
- `down_sample.py`: Downsample field data while preserving structure
  ```bash
  python down_sample.py --input input_field.npy --output output_field.npy --downsample-factor 32
  ```
- `field2bigfile.py`: Convert field data to BigFile format
  ```bash
  python field2bigfile.py --input field_data.npy --output output_bigfile --redshift 0.0 --Lbox-kpc 100000
  ```

## Data Formats

The pipeline supports multiple data formats:
- **BigFile**: Directory-based format containing Position and Velocity data
- **Field Data**: NumPy arrays (.npy) with shape (6, N, N, N) containing normalized displacement and velocity fields
- **Visualization Output**: PNG files showing 3D particle distributions

## Notes

- `lr2sr.py` assumes you use a GPU node. If you use a CPU node instead (which would be much slower), you might need to change `lr2sr.py#30` to `device = torch.device('cpu')`.

- Because of GPU memory limitations, we chunk the LR input to pieces of `nsplit^3` for SR operation. You can set the `nsplit` argument larger if out of GPU memory, but make sure that `nsplit` divides Ng_lr.

- The models are trained on WMAP9 cosmology (see `scripts/LR-sim/paramfile.genic`). It might extrapolate to other cosmologies, but this is not well calibrated yet.

- Visualization tools support LaTeX rendering for high-quality plots if LaTeX is installed on your system.

- The downsampling tools preserve the structure of the data while reducing the number of points, useful for visualization and analysis of large datasets.
